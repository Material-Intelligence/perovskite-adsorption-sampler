# The VASP stage

`perovml.dft.vasp` is a thin driver: it writes VASP inputs, optionally runs VASP, parses what comes
back, and can follow up with a Bader charge analysis. It is deliberately not a general VASP
interface — the INCAR templates encode the settings this workflow was built around, and you are
expected to override anything you disagree with.

The workflow calls it through `run_dft_stage` ([adsorption_workflow.md](adsorption_workflow.md));
this document is about the layer underneath, which is usable on its own.

## Generating inputs

```python
from ase.io import read
from perovml.dft.vasp import VASPRunner

atoms = read("outputs/adsorption/molecules/Acetone/mlp/best.vasp")
runner = VASPRunner(potcar_dir="/path/to/potpaw_PBE")
runner.generate_inputs(atoms, output_dir="dft/adslab", calc_type="scf",
                       incar_override={"DIPOL": "auto"})
```

That writes `INCAR`, `POSCAR`, `KPOINTS` and `POTCAR` into `dft/adslab`. With `potcar_dir` left
unset, `VASPRunner` falls back to `$VASP_PP_PATH`; with neither, `generate_inputs` raises rather than
writing a directory that cannot be submitted.

### INCAR

`calc_type="scf"` starts from `DEFAULT_INCAR_SCF`, `calc_type="opt"` from `DEFAULT_INCAR_OPT`, and
`incar_override` is merged over the top.

| Tag | SCF | OPT | Why |
|---|---|---|---|
| `PREC` | `Accurate` | `Accurate` | |
| `ENCUT` | `500` | `500` | eV. Set it from your POTCAR set's `ENMAX`, not from habit. |
| `EDIFF` | `1e-6` | `1e-6` | Electronic convergence, eV. |
| `NELM` | `200` | `200` | |
| `ISMEAR` / `SIGMA` | `0` / `0.05` | same | Gaussian smearing, appropriate for a semiconductor slab. |
| `IVDW` | `12` | `12` | DFT-D3 with Becke–Johnson damping. Molecular adsorption on a halide perovskite is dispersion-dominated; without this the binding is badly underestimated. |
| `LCHARG` | `.TRUE.` | `.FALSE.` | |
| `LAECHG` | `.TRUE.` | `.FALSE.` | All-electron density, needed for Bader. Only the single point writes it. |
| `NCORE` / `KPAR` | — | — | Not set. `NCORE` has to divide the cores per node, so a default picked here would be wrong on most machines; VASP's own defaults are safe. Set them for your node through `dft_incar_override`. |
| `IBRION` | — | `2` | Conjugate gradient. |
| `NSW` | — | `100` | |
| `EDIFFG` | — | `-0.03` | Force convergence, eV/Å. |
| `ISIF` | — | `2` | Relax ions, keep the cell. Correct for a slab. |

Three tags accept the literal string `auto` when the value comes from the workflow config:

- **`DIPOL: auto`** is replaced with the mean fractional coordinate of the structure, formatted to
  six decimals, which is the centre VASP's dipole correction expects for a slab with an adsorbate on
  one face. You still have to switch the correction on yourself with `IDIPOL` and `LDIPOL`.
- **`NSW`** and **`IBRION`** follow `dft_mode` when they are set to `auto` or left out of
  `dft_incar_override` entirely: `500` / `2` for `opt`, `0` / `-1` for `scf`. An explicit number is
  never overwritten. Note that this path overrides the `NSW = 100` of the `opt` template.

A generated single-point INCAR looks like this:

```
# INCAR generated by perovml
PREC = Accurate
ENCUT = 500
EDIFF = 1e-06
NELM = 200
ISMEAR = 0
SIGMA = 0.05
IVDW = 12
LCHARG = .TRUE.
LAECHG = .TRUE.
DIPOL = 0.546405 0.533619 0.285911
```

To run it on a 64-core node, add the parallel layout yourself:

```yaml
dft_incar_override:
  NCORE: 8
  KPAR: 1
```

### KPOINTS

A Gamma-centred mesh, `default_kpoints=(1, 1, 1)` unless you pass `kpoints=`. That is the right
choice for an isolated molecule and for the large supercells this workflow generates; it is not
right for a small cell, and nothing checks for you.

```
Automatic mesh
0
Gamma
1 1 1
0 0 0
```

### POSCAR and selective dynamics

`generate_inputs` accepts `selective_dynamics` as a boolean array of shape `(N, 3)`. Sites whose
three flags are all False are written as fixed. To build that block from a *z* cut instead, use
`perovml sd` or `perovml.utils.poscar_tools`, which work through pymatgen's `Poscar`.

### POTCAR

POTCARs are concatenated in order of first appearance of each element, reading
`{potcar_dir}/{variant}/POTCAR`. Each element has a preference list, tried in order, so that
semi-core variants win where they matter:

| Element | Tried in order |
|---|---|
| Pb | `Pb_d`, `Pb` |
| I | `I`, `I_sv` |
| Cs | `Cs_sv`, `Cs` |
| K | `K_sv`, `K_pv`, `K` |
| Na | `Na_pv`, `Na_sv`, `Na` |
| C, N, O, H | plain first, then `_s` |
| S | `S`, `S_h` |
| F | `F`, `F_s` |
| Cl | `Cl`, `Cl_h` |

Anything not in the table uses the bare element name. A missing POTCAR raises `FileNotFoundError`
naming the element and the variants that were tried — it never silently substitutes.

VASP POTCARs are licensed and are not distributed here. Point `potcar_dir` or `$VASP_PP_PATH` at
your own installation.

## Running and parsing

```python
result = runner.run("dft/adslab", vasp_cmd="vasp_std")
parsed = runner.parse_results("dft/adslab")
```

`run` splits `vasp_cmd` on whitespace and calls it directly, without a shell, in the input
directory, redirecting to `vasp.out` and `vasp.err`. It returns `success`, `returncode` and `error`.
When the job already runs under `srun`, use a plain `vasp_std` here — nesting `srun` inside `srun`
will not do what you want.

`parse_results` streams the OUTCAR once, reads the CONTCAR when present, and returns `energy` (the
last free energy `TOTEN`, in eV), `converged`, `electronic_converged`, `ionic_converged`,
`n_ionic_steps`, `n_electronic_steps`, `n_electronic_steps_last_cycle`, `nelm` and `error`, plus
`fmax` and `atoms` when they can be recovered.

`converged` answers "may this energy be used?", which is not the same question as "did VASP exit
cleanly". VASP returns 0 after exhausting `NELM` and still writes a perfectly ordinary `TOTEN`, so
`converged` requires both of:

- **electronic**: the last SCF cycle finished in fewer than `NELM` iterations;
- **ionic**: for a relaxation (`NSW > 0`, `IBRION >= 0`), the `reached required accuracy` marker. A
  single point has nothing to converge ionically and passes by definition.

When either fails, `error` says which. The workflow stage refuses to record an energy, to mark
`<stage>_done` or to compute an adsorption energy from a run that did not pass this check; the
reason is written to `status.json` under `dft_<stage>_error`.

## Bader analysis

Needs the [Bader code](https://theory.cm.utexas.edu/henkelman/code/bader/) on `PATH`. The accurate
route sums `AECCAR0` and `AECCAR2` into a reference density first, which is what `LAECHG = .TRUE.`
in the SCF template is for:

```python
from perovml.dft.vasp import combine_aeccar, run_bader, calculate_charge_transfer, load_zvals

combine_aeccar("dft/adslab/AECCAR0", "dft/adslab/AECCAR2", "dft/adslab/AECCAR.sum")
bader = run_bader("dft/adslab/CHGCAR", aeccar_path="dft/adslab/AECCAR.sum")

adsorbate_indices = [i for i, tag in enumerate(tags) if tag == 2]
transfer = calculate_charge_transfer(
    bader["charges"], atoms, adsorbate_indices, valence_electrons=load_zvals("dft/adslab")
)
```

The adsorbate is tag `2` in every structure this package produces, which is where
`adsorbate_indices` comes from. A POSCAR cannot carry ASE tags — reading one back gives every atom
tag `0` — so the workflow writes `mlp/best_tags.json` next to `mlp/best.vasp`, in the same atom
order, and that is where `tags` above comes from. `atoms` must be in the same order as the Bader
calculation, so read it back from the POSCAR or CONTCAR in that directory rather than reusing an
earlier object.

`combine_aeccar` shells out to `chgsum.pl` from the same distribution. `run_bader` returns
`charges` and `volumes` as arrays, plus `success` and `error`. `calculate_charge_transfer` subtracts
the free-atom valence-electron count from the Bader count over the adsorbate; a positive result
means the adsorbate gained electrons.

The reference counts must come from the POTCARs that were actually used: `generate_inputs` parses
the `ZVAL` field out of each POTCAR block it concatenated and writes the mapping to `zval.json` next
to the inputs, which `load_zvals` reads back. This matters — `_write_potcar` prefers `Pb_d`, which
carries 14 valence electrons, where the plain `Pb` carries 4, so guessing costs ten electrons per Pb
atom. `VALENCE_ELECTRONS` remains only as a per-element last resort; every element it has to supply
is logged as a warning and listed in the result's `assumed_elements`.

The workflow's own Bader stage (`run_dft_stage`) does all of this: it builds the AECCAR reference,
reads the tags side-car, loads `zval.json`, and refuses to mark `bader_done` when the adsorbate
cannot be identified, recording the reason in `status.json` under `bader_error`.
